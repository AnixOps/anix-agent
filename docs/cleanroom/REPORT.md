# Clean-room rewrite: report

Date: 2026-11-22. Repository: `AnixOps/anix-agent`. Forked project:
`wyx2685/V2bX` (MPL-2.0), branch `dev_new`; fork point `71277de`.

## 1. How "derived from upstream" was measured

1. The upstream branch was added as a remote and `git rev-list up/dev_new`
   gave the set of upstream commits (shared history, the repository is a
   GitHub fork).
2. `git blame -w -M -C --line-porcelain` was run on every tracked file; a
   line counts as upstream-attributed when its blamed commit is in that
   set. `-M -C` follows moved and copied lines, so a line that was only
   moved or copied from an upstream file still counts.
3. "Non-trivial" lines: more than 3 characters after removing whitespace.

`go.sum` is generated by the Go toolchain and is left out of both counts.

## 3. Similarity check against the upstream source

The upstream repository was cloned again at `71277de` only after every
implementer had finished. `similarity.py` normalises lines (whitespace
removed; imports, package clauses, comments and lines of 3 characters or
fewer dropped) and compares the files of the rewritten areas with every
upstream `.go`, `.yml`, `.json`, `.md` and `.sh` file: identical lines,
and runs of 3, 5 and 8 consecutive identical lines.

## 4. Process

- **Specification writer**: the Claude session that ran the audit. It had
  read the old code and wrote the six specifications in this directory
  (no upstream source in them), prepared the exports, copied the results
  back and opened the pull requests.

  specification and a `git archive` export with a new single-commit git
  history, from which the files in scope were deleted and the functions
  in scope removed with a `go/ast` tool (`rmfunc.go`). Each was told not
  to read the upstream project in any form, the repository history or any
  other directory, and reported every source it read.

## 5. Limits and disclosures

- **Earlier, non-clean-room rewrites.** #164 (command line, merged) and
  #165 (limiter/conf/panel/core, closed unmerged) were written by an agent
  that had read the upstream code. Both were redone here: #171 replaces
  every file of #164, and none of #165's code was merged (its commits stay
  reachable as `refs/pull/165/head`).
- **Same model family.** Specification writer and implementers are
  instances of the same AI model. They shared no conversation context, but
  a model may have seen public code during training. The similarity check
  above is the control for that.
- **History.** The repository's git history still contains the upstream
  commits and the old files; this work changes the current tree only.
- **Licence and fork relation** are unchanged by this work: `LICENSE`
  (MPL-2.0), the README attribution and the GitHub fork link are the
  owner's decisions now that the code is replaced.
- **Outside the areas.** `node/node.go` keeps 12 non-trivial attributed
  lines (`type Node struct {`, `func New() *Node {`, the `Start`/`Close`
  signatures, `for i := range nodes {`, `n.controllers = nil`); they are
  listed in the classification above. `GOOS=windows` builds fail in
  `upgrade/upgrade.go` (`syscall.O_NOFOLLOW`), as before this work;
  Windows is not a release target.

## 6. Owner decisions after the rewrite

Decided by the repository owner on 2026-11-22 (12:55 UTC), choosing the
recommended option for all three:

- **Licence:** `LICENSE` is the AGPL-3.0 text (as AnixOps Control adopts
  for 5.1); releases up to 5.0.8 stay available under MPL-2.0.
- **README:** the upstream acknowledgement is removed; a "许可证与历史"
  section states the fork origin, this rewrite and the licence of older
  releases and commits.
- **History:** kept as is (rewriting it would break every clone, tag and
  pull request reference); the README says that older commits contain
  MPL-2.0 code.
- **Fork relation:** the owner asks GitHub Support to detach the
  repository from the fork network; issues, pull requests and stars are
  kept by that process.
