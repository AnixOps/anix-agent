# 地区中继（region relay）

完整设计在 Control 仓库 `docs/design/region-relay/README.md`。本文只写需求与 Agent 侧的行为。

## 需求

来源：项目需求表 R33、R34（2026-11-25，由 owner 提出并确认）。

- **R33。** 地区内放一台中继机，主面板只与中继通讯，中继再与本地区的所有节点通讯。中继无网页界面、无 API，只做纯转发：面板与节点之间端到端认证和加密，中继看不到也改不了控制内容，不保存密钥和配置。两台中继互为备份。中继或面板不可达时，节点按最后一次配置继续运行。先做中国大陆。
- **R34。** 中国大陆的 Agent 一律经本地区中继连接面板，不回退直连。中继同时缓存签名的安装包和升级包，节点照常验签。

## Agent 的改动

| 需要 | 做法 |
|---|---|
| 拨号地址与证书名分离 | 已有：`GRPCHost` 是面板的 gRPC 目标，`GRPCServerName` 是校验面板证书用的名字。配置了中继后，这两项仍然写面板的，只有 TCP 连接改去中继 |
| 中继列表 | 新配置项 `GRPCRelays`（`host:port` 列表）。设置后，控制流和证书入网/续期（AgentEnrollment）的每条连接都只拨中继，不拨 `GRPCHost`，也不回退直连 |
| 选择与切换 | 第一次连接同时拨所有中继，用最先连上的一台（即最快的），其余记下耗时后关闭；之后每 10 分钟在后台复测，不占用拨号时间，只有另一台的耗时比当前低 30% 以上，新连接才换过去，避免来回切换 |
| 健康判断 | 中继先接受 TCP 再连面板，所以 TCP 连上不算可用。经这台中继收到面板的第一批字节（TLS ServerHello）才算可用；在此之前连接被关闭、读出错，或 5 秒内没有应答（中继挂起，不必等满 10 秒拨号超时），都算这台中继失败。中继连接上照常设置 TCP_USER_TIMEOUT（与控制流 keepalive 超时相同，10 秒）。失败的中继按 5 秒起、最长 5 分钟的指数退避跳过；复测只计时，不清除退避，也不会把新连接换到退避中的中继；所有中继都在退避时仍按顺序全部尝试。调用方自己取消或超时不算中继失败 |
| 多个节点身份 | 同一进程里配置相同中继列表的节点（`proxy-<id>`、`forward-<id>`）共用一个选择器，只测量一次；节点身份停止或换了列表后，不再使用的列表和它的升级缓存条目会被丢弃 |
| 入网 | `anix-agent join --relay <host:port>`（可重复）经中继入网，`--grpc` 仍是面板的目标和证书名；中继全部不通时按不可达退出（4），不直连 |
| 升级包缓存 | 新配置项 `ReleaseCaches`（https 基础地址列表）。升级时先向中继缓存按 SHA-256 取文件（`/v1/sha256/<sha256>?src=<发布地址>`），哈希不对就丢弃并换下一个来源；再走控制连接；最后走发布地址，但配置了 `GRPCRelays` 时，发布地址在面板的主机名（`GRPCHost`、`GRPCServerName`、`ApiHost`）下就不下载，以免绕过中继直连面板。每个缓存最多用剩余时间的三分之一，且不超过 5 分钟。同一进程里各节点身份的缓存列表合并使用，互不覆盖。无论来源，大小、SHA-256 和发布签名照常校验，信任根只在节点上 |
| 失联时 | 现有行为：最后一次应用的配置快照保存在本地（`api/agent/state`），控制流断开不会清空数据面，重连按退避进行 |
| 面板下发路由 | 面板在期望配置里下发成员 `control_route`（`{"relays": [...], "release_caches": [...], "direct": false}`，来自节点所在节点组）。Agent 收到后立即生效，不必重装：中继列表变了就保存，并结束当前会话，下一条连接经新中继；缓存列表交给升级。没有这个成员时保持现有路由。`relays` 为空或缺失**不表示直连**，Agent 保留当前中继并记警告（缓存照常更新）；只有显式 `"direct": true` 才去掉中继。无法使用的中继列表会被拒绝，现有中继不变。路由保存在流状态目录（`AgentStream.StateDir`）下的 `control-route-<节点身份>.json`，重启后优先使用它，所以直装的节点被面板改为经中继后，重启也不会回到直连；文件损坏时退回配置文件里的 `GRPCRelays` 和 `ReleaseCaches` |
| 生产校验 | `GRPCRelays` 必须是真实的 `host:port`，`ReleaseCaches` 必须是真实的 https 地址 |

配置示例（节点的一项）：

```json
{
  "ApiHost": "https://panel.company.net",
  "GRPCHost": "panel.company.net:50051",
  "GRPCUseTLS": true,
  "GRPCServerName": "panel.company.net",
  "GRPCRelays": ["relay-1.company.net:50051", "relay-2.company.net:50051"],
  "ReleaseCaches": ["https://relay-1.company.net:8443", "https://relay-2.company.net:8443"]
}
```
